# 硬证据规范（Evidence Log）

清理类工作最大的风险不是"没删干净"，而是**"以为自己删干净了"**。
本文件规定：每一步靠什么证据下结论，以及什么样的"确认"**不算**证据。

---

## 一、先建立正确认知：本地清理的可见性边界

**本地清理对服务端是零可见的。** 它不能"抹掉"服务端已有的记录，也不参与任何网络请求。

它的真实价值只有一句话：

> **让新号登录时不带着旧指纹上去。**

据此可以推出两条硬结论：

| 路径 | 服务端能看到什么 |
|---|---|
| **命令行（CLI）** | 出口 IP + 凭证 + 客户端版本。**不带指纹、不带 Cookie** |
| **浏览器路径** | 可见信号多得多：Cookie、设备 ID、登录检测标记、canvas/字体指纹等 |

所以：
- CLI 侧的 `machineID` / `userID` 清得再干净，**也改变不了服务端已记录的历史**
- 真正影响"新号被认成谁"的，是**下一次登录时带上去的东西**

**封号归因必须成组替换锚点。** 五层锚点：出口 IP / 设备指纹 / 支付主体 / 邮箱域 / 使用行为。
**单锚点替换无效** —— 换了 IP 但设备指纹还在，等于告诉服务端"同一个设备换了个出口"。

清理只解决其中**一层**。这一点必须对用户讲清，否则会让他误以为"清干净就万事大吉"。

---

## 二、证据分级

| 级别 | 形式 | 强度 | 用途 |
|---|---|---|---|
| **L1 存在性** | `[ -e ]` / `[ -L ]` | 弱 | 快速筛查，易受 A7（断链）坑 |
| **L2 计数** | `grep -c` / SQL `count(*)` | 中 | 量化"删了多少" |
| **L3 字节** | `grep -c -a` 二进制扫描 | 强 | 抓 BLOB、tombstone、未 VACUUM 页 |
| **L4 摘要校验** | `md5` 前后对照 | 最强 | 证明"备份 == 清理前状态" |

**结论必须建立在 L2 以上。** 只报"我看过了，干净"不构成证据。

---

## 三、各阶段的标准证据

### Stage 0 普查
- 每个命中项的**完整路径**（不是"有一些文件"）
- 身份键的**存在性与条数**（**绝不打印值**）
- 多 `ant-did` 场景：给出**数量**并指明"只清一处等于没清"

### Stage 1 备份
- 备份目录**绝对路径** + 体积
- 关键身份文件的 **md5**（写入 `MD5SUMS.txt`）
- 校验命令：`cd "$BK" && md5 -c MD5SUMS.txt`

### Stage 2/3 删除
- **前 → 后**对照：

| 对象 | 前 | 后 | 手段 |
|---|---|---|---|
| Chrome sqlite 行 | 602 | 0 | SQL DELETE + VACUUM |
| Preferences key | 39 | 0 | JSON 精删 |
| Local Storage key | 119 | 0 | LevelDB del + 整目录删 |
| LaunchServices | 87 | 1 | `lsregister -u` 逐个注销 |

- 每个 FAIL 项都要列出，**不许"总体成功"糊过去**

### Stage 5 终检
- `verify_reset.py` 的**退出码**（0 = PASS）
- 七维度逐项计数
- 噪声单独列出（不计入实质残留）

## 五、反模式（这些**不算**证据）

| 说法 | 为什么不算 |
|---|---|
| 「我已经检查过了」 | 无量化，无法复核 |
| 「应该没有残留了」 | 推测 ≠ 观测 |
| 「命令返回 0」 | 多个坑会**静默失败并返回 0**（见 A5、B2） |
| 「只看了 Default profile」 | 严重假阴性来源（见 browser-layer.md 铁律） |
| 「SQL 层面 0 命中」 | BLOB / 未 VACUUM 页仍可能有字节（见 C1、C2） |
| 「删了报错但应该没事」 | FAIL 必须列出并处理 |

---

## 六、有意保留项要**显式声明**

清理不可能"全 0"。凡是不删的，必须给出**理由**并单列，否则下次复检会被当成漏网：

| 保留项 | 理由 |
|---|---|
| npm cacache 里的包名 | 依赖名噪声，对服务端不可见，删了会被重写 |
| LaunchServices 残留注册 | 无害失效项，注销后仍会由系统重建 |
| 用户自己的 n8n / 代理配置里含 "claude" | 是**分流规则或路径字符串**，不是痕迹 |
| Chrome IndexedDB 里的浏览数据 | 文件名（origin）非 claude.ai，内容命中属用户数据 |
| 项目级 `~/<project>/.claude` | 用户工作产物 |

> **判据：删它会不会破坏用户的东西？会 → 保留并声明。删它对反关联有没有收益？没有 → 保留并声明。**
