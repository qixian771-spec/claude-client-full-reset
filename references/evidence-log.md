# 验收证据报告

按本次路线填写，未执行写“未执行”，不适用写“不适用”。不凭计划、模拟或其他机器结果补造实际验收。

| 项目 | 必填内容 |
| --- | --- |
| 目标与路线 | 仅检测 / A 配置 / B 检查 / C 清理 / D 恢复；用户目标及约束 |
| 具体范围 | 路径、浏览器、profile、保留项；授权来自本次或此前哪项明确要求 |
| 前提 | 平台（macOS/Windows 及版本）、所需依赖、执行宿主、应用退出（Windows 含托盘与后台 Edge）和必要权限；未满足项 |
| 环境检测 | 真实退出码与 status；观察结果、`unclassified_items`、`auto_memory_projects`、凭证位置存在与否、`CLAUDE_CONFIG_DIR` 提示；不把 0 当作未安装 |
| 备份 | 本次需要时记录目录、完整校验及目标覆盖；不需要则不适用 |
| 预览 | 实际命令、退出码、匹配范围/条数；是否与批准清单一致 |
| 执行 | 每步命令与退出码、已完成/失败/未执行目标；不要混成一条成功状态 |
| 验收 | 使用下表对应标准；写明所验证的层级与证据 |
| 未覆盖 | 按实际范围明示，不能描述为已清零或已验证 |
| 后续与恢复 | 未完成事项的具体前提；存在备份时给恢复位置与选择器，不自动执行 |

## 按路线使用不同的成功标准

| 路线 | 可验收的结果 | 不可替代的结论 |
| --- | --- | --- |
| 环境检测 | 检测完成，候选路径/缺口及未知项已解释 | 安装能用、能登录、从未用过、账号无异常 |
| A 配置 | 已授权的依赖、安装或配置变更完成并验证；分开列路径、启动、联网、登录层级 | 仅路径存在就称全部可用；未启动就称运行成功 |
| B 检查 | 已授权范围扫描完成，命中、保留理由、错误和未查项清楚 | 已清理或全机无痕迹 |
| C 清理 | 指定目标操作结果；完整验收另需对应命令实际通过 | 单项删除成功替代全范围 PASS |
| D 恢复 | 所选目标与可信备份一致，其他保留项未纳入恢复 | 恢复后清理扫描必须为零 |

只有对应命令实际完成且其覆盖范围无命中时，才可写“所列范围清理验收通过”。有意保留项导致 REVIEW 时说明原因，不为拿到 PASS 继续删数据。部分完成、等待应用退出、读取失败均如实单列。

开发测试与用户机器的实际验收不同。仓库测试证明受测逻辑符合契约；文档路线推演不是独立 AI 实机验收，二者都不能替代使用者的实际路径、权限、版本及备份验证。

用户报告和备份默认只在本地交付；只有明确授权发布特定内容时才上传，不随代码提交夹带私人日志。
