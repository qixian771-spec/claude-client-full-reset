# 常见故障处理

| 现象 | 正确处理 |
| --- | --- |
| 环境检测退出 1 | 有异常或基础依赖待处理；按报告具体原因处理，不进入写入 |
| 痕迹扫描/清理验收退出 1 | 扫描存在命中，或只读扫描发现相关进程；逐项判断，不等于可删除 |
| 其他操作退出 1 | 不具有“有命中”的通用含义，按失败处理；见 [执行手册](agent-runbook.md) |
| 退出 2 或其他非零错误 | 停止；根据报错修复输入、权限、进程、依赖或数据问题 |
| Claude Code 自己或内置终端宿主仍在运行 | 保存清单并转独立 Terminal/iTerm，正常退出相关应用；不绕过进程检查 |
| 局部清理后整包恢复被拒绝 | 用 `--restore BACKUP --path 原目标 --dry-run` 预检，仅恢复所需目标；不移走无关配置 |
| 所选恢复目标仍存在 | 保留当前内容；核查是否需另行备份并移走该目标；不合并覆盖，数据库按恢复说明处理 |
| 恢复复制中断 | 保留可能的不完整目标与备份，检查前序已完成项目；不得直接整批重跑或自动删除冲突 |
| macOS 读取或 Finder 自动化权限拒绝 | 按 [首次准备](first-run.md) 定位执行宿主及必要权限；不升级为强制删除 |
| `ps` 失败 | 无法判断进程状态，禁止继续修改 |
| 备份不一致 | 保留失败现场，不用另一复制命令接着做；确认源稳定后重新备份 |
| 备份目录没有 manifest.json | 未完成备份，不能授权清理 |
| 原始目标自备份后变化 | 关闭应用并重新检查、备份；不得手动刷新 manifest 掩盖变化 |
| `--profile` 拼错 | 更正具体目录名；不能自动切换到所有 profiles |
| SQLite 触发器、外键、虚拟表 | 停止自动精删，单独审阅 schema 与清理方案；不要禁用约束 |
| SQLite VACUUM 失败 | 返回错误；删除可能已提交，依备份与当前状态判断恢复需求 |
| LevelDB 打开失败 | 检查锁、进程、数据库完整性与依赖；不得当成没有 key |
| 字节命中而 SQL 无命中 | 可能来自 schema、BLOB、编码或旧页；不是自动删整库的理由 |
| 文件不存在、路径为符号链接或系统保护目录 | 拒绝移动，重新确认目标；不要改用强制删除 |
| Finder 拒绝 | 停止，报告错误；不换用永久删除 |
| 已安装同名 skill | 安装器拒绝覆盖；检查旧安装后由用户安排迁移 |

禁止 `except: pass`、失败后返回空结果、`|| true`、校验失败后仅打印清单、截断输出掩盖失败。

缺少可选路径与读取失败必须区分：只有明确的 FileNotFoundError / ENOENT 可以表示不存在；权限错误要向上传播。默认值只用于未提供的可选参数，不能代替失败结果。
