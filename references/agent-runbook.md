# AI 执行手册：检测 → 选路 → 任务卡 → 执行 → 测试 → 验收 → 交付

这是本 skill 的执行编排。先按用户目标选择一条路线，不把所有章节当作必须依次运行的脚本。各条命令均以本 skill/源码根目录为工作目录；下面的 `/absolute/...` 是模板，必须替换为本次已核实的路径后才能执行。

命令按 macOS 书写。**Windows**：`python3 scripts/X.py` 写成 `py -3 scripts\X.py`；`bash scripts/X.sh` 写成 `py -3 scripts\X.py`（Windows 没有 `.sh` 包装）；路径写成 `C:\...`；在 PowerShell 用 `$LASTEXITCODE` 读退出码。规则、退出码、停止条件两个平台相同。

## 0. 接收任务：先提取约束，不先重置

从当前及此前对话提取以下信息，已有信息直接沿用，不重复询问：

| 输入 | 记录内容 | 缺少时 |
| --- | --- | --- |
| 用户目标 | 环境检测、首次配置、检查残留、清理/重置、恢复、卸载 | 先做只读检测；只在后续路线确实不明确时问一句 |
| 目标产品与平台 | Desktop、Claude Code CLI、本 skill；macOS 或 Windows；不要把 Desktop 默认改成 CLI | 只读检查可先进行；平台以检测 JSON 的 `platform` 为准；实际安装前确认产品 |
| 当前限制 | 不联网、不启动 Claude、不关正在用的软件、不动代理/防火墙等 | 默认保留现有环境；用户明确限制一直生效，直到用户改变 |
| 已授权操作 | 检查、安装、具体修改、具体清理或恢复范围 | 缺少写入授权时只做到可审阅计划，不能靠检测结果推断授权 |
| 已知路径和备份 | 来源目录、安装目录、profile、备份目录及证据 | 查清真实路径；不能编造路径或使用模板占位符执行 |

检查运行位置：应能看到本目录的 `SKILL.md` 和 `scripts`。先读 [首次准备](first-run.md)，确认 Python 3.10+。Python 缺失时不能运行 Python 检测器；给出准确准备步骤，或在用户已授权安装依赖的范围内处理。不能把解释器不可用解释为没有 Claude。

**当前任务只需要检查或编写说明时，不为了演示去清理真实数据，也不为做测试而退出用户软件。**

## 1. 环境检测：完整报告与退出码一起判断

读取 [环境检测与配置](environment-check.md)，运行一次：

```bash
python3 scripts/check_environment.py --json
```

同时保留实际退出码、stdout 和 stderr。不要用管道截断、`|| true` 或另一个命令的退出码代替它。JSON 是观察结果，不是下一步修改授权。

按以下顺序判断：

1. 退出 **2 或其他异常码**、输出缺失、JSON 无法解析：停止依赖该检测的后续动作，报告具体错误；没有可用结论。
2. 退出 **1**：读取 `issues`、`missing_base_tools`、`python.supported`。区分路径异常和依赖缺少。只安排已授权的原因修复，不进入备份/清理/恢复。修复后重新检测；没有修复不能原样循环重试。
3. 退出 **0**：读取 `status`、`desktop_paths`、`cli_candidates`、`cli_install_dirs`、`local_paths`、`unclassified_items`、`auto_memory_projects`、`credential_locations`、`registered_apps`、`related_process_count`、`next_steps`，再按下表与用户意图共同选路。`unclassified_items` 只是名称清单，不是异常也不是清理目标；`auto_memory_projects` 大于 0 时，任何涉及 `projects` 的计划都要单独列出自动记忆的取舍。
4. `status=needs_review` 即使与退出码矛盾，也停止写入并核实报告来源；不能猜成正常状态。

| status | 可以作出的判断 | 不能作出的判断 | 下一步 |
| --- | --- | --- | --- |
| `not_detected` | 常见位置未发现所列候选和数据 | 从未装过、从未用网页、账号正常 | 检测任务结束；明确要求首次配置才进入 A |
| `installed` | 发现安装候选路径 | 安装完整、版本合格、能联网登录 | 检测任务结束，或按已授权目标进入 A/B/C/D |
| `local_data_only` | 有配置/数据，但常见路径未找到安装 | 一定用过、一定卸载过、这些都是垃圾 | 先 B 审阅；明确要恢复时可走 D |
| `needs_review` | 有异常或覆盖不确定 | 可以忽略异常后继续操作 | 停止写入，处理具体原因 |

用户要求恢复时，不因 `installed` 或 `local_data_only` 就先执行清理。用户只要求检测时，报告后结束，不自动接上安装、浏览器扫描、备份或重置。

进程数量大于 0 不妨碍环境检测。它提示写入阶段有退出前提，不是让 AI 结束进程的指令。

## 2. 建立本次任务卡

在对话或用户允许的工作目录记录，不把私人路径、凭证、日志提交到公开仓库。按所选路线只填写需要的字段；不适用项写“不适用”，不要造一个空备份。

```text
目标与路线：仅检测 / A 配置 / B 检查 / C 清理 / D 恢复
用户约束：
已有授权：
执行宿主与源码目录：
检测结论、退出码及未覆盖范围：
目标产品：
具体路径 / 浏览器名称 / profile 目录名：
保留项：
备份目录与校验结果：
执行步骤及每步通过条件：
停止条件：
验收标准：
结果：未开始 / 等待前提 / 部分完成 / 已完成 / 失败
```

实际命令必须使用已核实的参数。能用工具的参数数组就用参数数组；使用 shell 时正确引用含空格或特殊字符的路径，禁止 `eval`。多路径选择须列出每一项，不用未审阅的通配符代替。

## A. 环境准备 / 首次配置路线

**进入条件**：用户明确要求准备或配置，目标产品已确定。检测仅报告缺口时，交付配置清单即可，不默认代装。

1. 阅读 [首次准备](first-run.md) 与 [环境检测与配置](environment-check.md)。把本 skill 的 Python/Git/可选 LevelDB 依赖，与 Claude Desktop/Claude Code 自身条件分开。
2. 对照官方当前安装说明选择**一种**安装方式，记录目标、来源、要新增或修改的路径以及验收方式。安装范围已有授权就执行；不能因某一步有写入就重新索要整项已有授权。
3. 用户不允许联网时，仅完成离线准备和清单，明确下载/在线验证尚未做。不要请求远端服务来“顺便验证”，也不换用来源不明的缓存包。
4. 保留已有安装、配置与 shell 文件。PATH 问题先核对检测报告的 `cli_candidates[].on_path`；不要通过重装、覆盖 shell 配置或改代理来掩盖路径问题。需要具体修改时展示差异并限定在已授权范围。
5. 安装或依赖准备错误就停止，报告失败步骤和当前状态；不自动改来源、换版本、换安装工具或放宽验证。
6. 再做环境检测，核对候选路径与依赖缺口是否符合计划。要执行 Claude、版本检查、启动或登录验证，必须符合用户对启动和联网的约束。路径检测不能代替运行验证；账号登录由用户操作。

**交付标准**：逐项说明已准备依赖、已安装/已配置项目及其证据，另列未执行的启动/联网/登录。只有实际验证过的层级才能写“通过”。没有本地数据时，A 路线不调用 `backup.sh` 或任何清理器。

## B. 检查 / 残留审阅路线

**进入条件**：用户要求检查，或要为已授权清理界定范围。读 [覆盖矩阵](coverage-matrix.md)。

先选择本次扫描范围，不要把三条命令全跑一遍：

| 条件 | 命令 | 判断 |
| --- | --- | --- |
| 用户同意浏览器范围，且浏览器已正常退出 | `bash scripts/scan_readonly.sh`（Windows：`py -3 scripts\scan_readonly.py`） | 0 无命中；1 有命中或相关进程需审阅；2 失败 |
| 用户明确排除/暂缓浏览器检查 | 同上加 `--no-browser` | 必须记录浏览器未查，不是全范围通过 |
| 只检查浏览器，且已退出浏览器 | `python3 scripts/browser_scan.py` | 0 无命中；1 有命中；2 失败 |

`--deep` 仅在需要扩大到文档列明的 Chrome HTTP 缓存范围时添加，不能把它说成全机深度取证。用户要求不关闭正在用的浏览器时，保留软件运行；可以交付环境检测结果和待执行扫描，不能擅自切成排除浏览器后称任务全部完成。

把命中转成“路径/类别、用途线索、影响、拟保留或拟处理”的清单。关键词命中不是删除授权；技能、设置和正常人名也不是自动清理对象。

**交付标准**：命中、保留项、读取失败、未覆盖项分开报告。用户只要检查时到这里结束；不要继续 C。

## C. 备份与清理路线

**进入条件**：已有具体授权清单；相关应用已正常退出；执行宿主和源码在待清理范围外。使用 [恢复说明](restore-and-rebuild.md) 了解恢复条件。

### C1. 交接独立终端

在 Claude Code 或 Code/Cursor/Windsurf 内执行时，不可能一边保持宿主运行，一边满足本工具全部写入前提。保存任务卡，将以下内容交给独立终端（macOS：Terminal/iTerm；Windows：Windows Terminal/PowerShell，不用管理员身份）：平台、源码绝对目录、已经批准的目标、保留项、备份命令、预览命令、执行及验收顺序、每步停止条件。不要只给一句“退出再运行”。

由用户保存工作、正常退出相关应用（Windows 还包括托盘里的 Claude 和后台常驻的 Edge，见 [首次准备](first-run.md#52-退出相关应用)）。若用户仍要使用它们，状态为“等待退出前提”，不自动结束进程或绕过保护。应用关闭前可完成说明和清单，不能提前写入。

### C2. 创建一次覆盖本批目标的备份

- 只处理默认客户端清单：`bash scripts/backup.sh`。
- 含浏览器 profile 或其他非默认目标：同一次备份中用重复 `--include` 明确加入，例如 `bash scripts/backup.sh --include "/absolute/browser/Default"`。
- 指定父目录时使用 `--dest /absolute/existing/backup-parent`；父目录需存在且位于所有来源之外。不要连续执行文档中的几个例子制造多份意义不明的备份。

只有命令成功且打印完整备份目录才记录它；随后执行：

```bash
python3 scripts/backup.py --verify /absolute/backup-directory
```

退出 0 后才进入下一步。备份目录没有 `manifest.json`、校验失败或没有数据可备份，都不是可以继续写入的条件。记录准确目录，不靠最新修改时间猜测，也不修改 manifest。

### C3. 文件/目录移动分支

对清单中每个明确目标核对备份覆盖：

```bash
python3 scripts/backup.py --check-path /absolute/approved/path --backup /absolute/backup-directory
```

通过后预览本批清单：

```bash
bash scripts/trash_paths.sh --dry-run /absolute/approved/path
```

确认预览和已经授权的范围一致，才执行同一清单：

```bash
bash scripts/trash_paths.sh --apply --backup /absolute/backup-directory /absolute/approved/path
```

每批 1–10 项；多项作为独立参数传递。禁止把 `.claude` 中个别路径的授权扩大成整个 `.claude`。预览出现“含 N 个项目的自动记忆”时，先向用户确认这些记忆的取舍。macOS 的 Finder 授权失败按 [首次准备](first-run.md) 定位具体权限；Windows 回收站拒绝（非固定磁盘、回收站设为直接删除、永久删除确认框选了“否”）就停止。两者都不能改用永久删除。

### C4. SQLite / LevelDB 精删分支

仅当用户选择数据库记录级处理时进入，先读 [浏览器规则](browser-layer.md)。确认显示名称与 profile 目录名，命令使用固定选择器；无选择器意味着全范围，不能为避免拼写错误删掉选择器。

```bash
python3 scripts/chrome_purge.py --browser Chrome --profile Default
```

只有预览成功并审阅命中范围后，才以相同选择器增加 `--apply --backup /absolute/backup-directory`。LevelDB 对应入口为 `node scripts/ls_purge.js`，同样先预览后执行，依赖需已准备；Windows 默认通过 `py -3` 调用 Python，可用 `CLAUDE_RESET_PYTHON` 指定解释器。输出 `[EMPTY]` 表示该 profile 的库从未建好，按 0 条处理。

SQL/LevelDB 预览退出 0 只表示预览成功，是否有匹配需读输出条数。SQL 文本、LevelDB key 精删均不是整库无痕承诺。不要因为出现触发器、外键、损坏库、锁或权限失败，就扩大为删库、删 profile 或关闭约束。

### C5. 清理验收

始终核对每一步的实际退出码与已完成目标。多目标不具备整体事务。失败时保留备份和现场，立即记录哪些完成、哪些失败、哪些没执行，不自动回滚、重跑或重新生成清单。

已完成写入且前提满足时，可按用户范围选择：

- 常规覆盖范围：`python3 scripts/verify_reset.py`。
- 原计划包含文档列明缓存范围：加 `--deep`。
- 用户明确要求卸载并且应用/CLI 已移除：加 `--uninstalled`。

只运行适合本次目标的验收，不能默认跑三个。退出 1 是仍有命中需审阅；废纸篓或保留配置仍被报告时，列出保留理由，不为拿到 PASS 继续删除。

只做了局部目标、浏览器未授权扫描或退出前提未满足时，报告“指定目标操作完成/全范围未验收”，不能虚构全范围 PASS。对应恢复位置与方法也要交付。

## D. 恢复路线

**进入条件**：用户要求恢复、可信旧备份位置已确定。先读 [恢复说明](restore-and-rebuild.md)，不要先走清理路线。

1. `python3 scripts/backup.py --list /absolute/backup-directory`：完整校验后查看来源，只读，不要求退出应用。失败就停止。
2. 选定原绝对路径，可为备份内子文件/子目录。局部恢复使用重复的 `--path`；没有明确整包恢复需求时，不省略选择器。
3. 相关应用正常退出，在独立终端运行预检：

   ```bash
   python3 scripts/backup.py --restore /absolute/backup-directory --path /absolute/original/target --dry-run
   ```

4. 预检通过，且范围已有授权后，运行同一命令去掉 `--dry-run`。不要加入不存在的 `--apply` 或 `--force` 恢复参数。
5. 目标仍存在时停止。不能删除其他配置来满足整包恢复；SQL/LevelDB 需要按恢复说明保持主文件及配套文件一致，不能直接覆盖数据库单文件。
6. 实际恢复会逐项验证；需要独立复核指定目标时，用 `backup.py --check-path ORIGINAL --backup BACKUP`。失败即报告局部状态，不自动删除不完整副本或扩大目标。

**恢复的验收标准是与选定备份一致，不是清理扫描为零。** 恢复后原来的 Claude 记录重新出现是预期现象，不能再次删除来取得清理 PASS。

## 3. 各命令退出码：必须按入口解读

| 入口 | 0 | 1 | 2/其他异常 |
| --- | --- | --- | --- |
| `check_environment.py` | 检测完成且无基础准备问题；可仍有安装/数据 | 异常或基础依赖待处理 | 检测失败，不能得出未安装结论 |
| `scan_readonly.sh` / `scan_readonly.py` | 所查范围无命中且无相关进程 | 命中/相关进程需审阅 | 检查失败 |
| `browser_scan.py` | 所查范围无命中 | 有命中 | 检查失败 |
| `verify_reset.py` | 所列范围 PASS | 仍有命中 REVIEW | 验收失败 |
| `backup.py`、`trash_paths.sh` / `trash_paths.py` | 指定操作或预览成功 | 不是正常成功状态，按失败处理 | 失败，检查可能已完成的前序项 |
| `chrome_purge.py`、`ls_purge.js` | 操作或预览成功；需另读匹配条数 | 不是“有命中”约定，按失败处理 | 失败，可能部分库已提交 |

未知参数、命令缺失、超时、读取失败均停止。命令输出中有 `[OK]` 不代表后来没有出错，必须核对整条命令的最终退出码。

## 4. 任务完成与失败交付

按 [证据报告](evidence-log.md) 填写本次路线的结果。最终至少说明：具体做了什么、实际验证了什么、哪些保持原状、哪些尚未检查或执行、备份及恢复入口（如果本次存在）。不要输出 cookie、token、环境变量值、原始进程参数或数据库 key/value。

- 检测完成：明确是环境报告，不宣称安装可用、账号正常或从未使用。
- 配置完成：把文件/路径检查、真实启动、联网、登录分别报告；没有做就写未做。
- 检查完成：命中是线索，不是已经删除。
- 清理完成：具体目标与所覆盖验收结果一致；保留项和范围外必须明示。
- 恢复完成：选定目标与备份一致；不是“再次清零”。
- 失败/等待前提：保留现场与已完成工作，指出一个具体阻碍及所需下一步；没有状态变化不重复运行同一失败命令。

“提交”指用户要求的交付目的地。只有明确要求提交代码或发布时才进行 Git/GitHub 操作；终端输出、检测 JSON 和用户备份不自动上传。

## 5. 路线自查例子（文档推演，不是真机演示指令）

| 输入情景 | 应选路线和行为 | 明确不能做 |
| --- | --- | --- |
| 新机器，只问是否装过 | 检测并报告未发现与范围边界，结束 | 自动安装或创建空备份 |
| 新机器，要配置 Desktop | 检测 → A，使用 Desktop 官方说明 | 转装 CLI、强制装 Node |
